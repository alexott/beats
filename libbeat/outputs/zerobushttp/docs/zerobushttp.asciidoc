[[zerobushttp-output]]
=== ZeroBus HTTP Output

The ZeroBus HTTP output sends events to a ZeroBus ingest endpoint using HTTP POST requests. Each event is sent individually as a JSON payload to the configured ZeroBus URI.

==== Example Configuration

[source,yaml]
----
output.zerobushttp:
  zerobus_uri: "your-workspace-id.ingest.cloud.databricks.com"
  table_name: "unity.default.air_quality"
  pat_token: "your-pat-token"
  workspace_url: "https://your-workspace.cloud.databricks.com"
  timeout: 30s
  batch_size: 1
----

==== Configuration Options

[options="header"]
|=======================
|Name |Description |Type |Default |Required
|`zerobus_uri` |ZeroBus URI endpoint (e.g., workspace-id.ingest.cloud.databricks.com) |string | |Yes
|`table_name` |Full table name in format 'catalog.schema.table' |string | |Yes
|`pat_token` |Personal Access Token for authentication |string | |Yes
|`workspace_url` |Databricks workspace URL |string | |Yes
|`timeout` |HTTP request timeout |duration |30s |No
|`batch_size` |Number of events per batch |int |1 |No
|`headers` |Additional HTTP headers |map |{} |No
|`retry.max` |Maximum number of retries |int |3 |No
|`retry.backoff` |Backoff duration between retries |duration |1s |No
|`ssl` |TLS/SSL configuration |object | |No
|`codec` |Event encoding configuration |object | |No
|`queue` |Queue configuration |object | |No
|=======================

==== ZeroBus URI Configuration

The `zerobus_uri` can be specified in different formats:

* Basic format: `your-workspace-id.ingest.cloud.databricks.com`
* With protocol: `https://your-workspace-id.ingest.cloud.databricks.com` (protocol will be stripped)
* Custom endpoints: Any valid ZeroBus endpoint URI

==== Table Name Format

The `table_name` must follow the Unity Catalog format: `catalog.schema.table`

Examples:
* `unity.default.air_quality`
* `production.analytics.user_events`
* `staging.logs.application_logs`

==== Authentication

The output uses Personal Access Token (PAT) authentication as required by ZeroBus. The token is sent in the `Authorization` header as a Bearer token.

==== Required Headers

The output automatically sets the following required headers:

* `Content-Type: application/json`
* `Authorization: Bearer <pat_token>`
* `unity-catalog-endpoint: <workspace_url>`
* `x-databricks-zerobus-table-name: <table_name>`

==== Optional Headers

Additional custom headers can be configured:

[source,yaml]
----
output.zerobushttp:
  zerobus_uri: "your-workspace-id.ingest.cloud.databricks.com"
  table_name: "unity.default.air_quality"
  pat_token: "your-pat-token"
  workspace_url: "https://your-workspace.cloud.databricks.com"
  headers:
    X-Custom-Header: "custom-value"
    X-Environment: "production"
----

==== Retry Configuration

The output supports configurable retry logic for transient failures:

[source,yaml]
----
output.zerobushttp:
  zerobus_uri: "your-workspace-id.ingest.cloud.databricks.com"
  table_name: "unity.default.air_quality"
  pat_token: "your-pat-token"
  workspace_url: "https://your-workspace.cloud.databricks.com"
  retry:
    max: 5
    backoff: 2s
----

==== TLS/SSL Configuration

TLS configuration is supported for secure connections:

[source,yaml]
----
output.zerobushttp:
  zerobus_uri: "your-workspace-id.ingest.cloud.databricks.com"
  table_name: "unity.default.air_quality"
  pat_token: "your-pat-token"
  workspace_url: "https://your-workspace.cloud.databricks.com"
  ssl:
    certificate_authorities: ["/path/to/ca.pem"]
    certificate: "/path/to/client.pem"
    key: "/path/to/client.key"
    verification_mode: full
----

==== Codec Configuration

The output supports custom JSON encoding:

[source,yaml]
----
output.zerobushttp:
  zerobus_uri: "your-workspace-id.ingest.cloud.databricks.com"
  table_name: "unity.default.air_quality"
  pat_token: "your-pat-token"
  workspace_url: "https://your-workspace.cloud.databricks.com"
  codec.json:
    pretty: true
    escape_html: false
----

==== Error Handling

The output handles different types of errors:

**Retryable Errors:**
* Network timeouts
* HTTP 5xx server errors
* HTTP 429 (Too Many Requests)
* Connection refused

**Non-retryable Errors:**
* HTTP 4xx client errors (except 429)
* Invalid JSON encoding
* Configuration errors
* Authentication failures (401, 403)

==== Response Handling

Successful ingestion returns:
* HTTP 200 status
* Response body: "Successfully ingested record."

==== Performance Considerations

* Default batch size is 1 (one event per request) as per ZeroBus API
* Connection pooling is enabled for better performance
* Configurable timeout and retry settings
* Memory-efficient JSON encoding

==== Complete Example

[source,yaml]
----
output.zerobushttp:
  zerobus_uri: "your-workspace-id.ingest.cloud.databricks.com"
  table_name: "unity.default.air_quality"

----

==== Troubleshooting

**Common Issues:**

1. **Authentication Errors (401/403):**
   - Verify PAT token is valid and has proper permissions
   - Check workspace URL is correct

2. **Table Not Found (404):**
   - Verify table name follows catalog.schema.table format
   - Ensure table exists in Unity Catalog

3. **Connection Timeouts:**
   - Increase timeout value
   - Check network connectivity to ZeroBus endpoint

4. **Invalid Table Name Format:**
   - Ensure table name has exactly 3 parts separated by dots
   - Verify catalog, schema, and table names are not empty

**Debug Logging:**

Enable debug logging to troubleshoot issues:

[source,yaml]
----
logging.level: debug
logging.selectors: ["zerobushttp"]
----
